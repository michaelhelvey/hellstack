# Pi tool mapping for pstack

pstack skills are written in Claude Code tool language (the `Skill` tool, the `Agent` tool,
`AskUserQuestion`, Claude model names). On Pi the skills are the same files, loaded from the pstack
package. Read this file when a pstack skill names a Claude tool, a driver or bundled skill, or a
Claude model. This file is Pi-specific.

On this machine, the `herdr-agents` extension of hellstack supplies the subagents. Each subagent is
an interactive pi session in its own herdr pane. The pstack extension does not supply an `agent`
tool.

## Tool actions

| pstack / Claude action                                                                        | Pi equivalent                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Read a file                                                                                   | `read`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Create a file                                                                                 | `write`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Edit a file                                                                                   | `edit` (exact text replacement)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Delete a file                                                                                 | `bash` (`rm`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Run a shell command                                                                           | `bash`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Search file contents / find files                                                             | `grep`, `find`, and `ls` when enabled, otherwise `bash` (`rg`, `grep`, `find`, `ls`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Fetch a URL                                                                                   | `web_fetch` when enabled, otherwise `bash` with `curl` / `wget`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Search the web                                                                                | Pi has no web search tool. Use an MCP server that provides one.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Invoke a skill (the `Skill` tool, `/command`)                                                 | Skills load natively. The model reads a skill when its description matches; `/skill:<name>` forces one.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Dispatch a subagent (the `Agent`/`Task` tool)                                                 | `subagent_start`. Give it a `title`, a `group`, and the full `task`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Dispatch N parallel subagents in one turn                                                     | N `subagent_start` calls in one response, with the same `group`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Wait for a subagent result                                                                    | When a subagent stops, its status and last reply arrive as a message, so do not poll. Use `subagent_wait` with the ids only when you cannot continue without the results. `subagent_read` shows the last messages of a subagent.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Continue or steer a subagent (`SendMessage`)                                                  | `subagent_send`. A message to a closed subagent resumes it with its full history.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| List subagents                                                                                | `subagent_list`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Stop a subagent                                                                               | `subagent_stop`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Track tasks (the todolist; `TaskCreate` / `TaskUpdate`, or `TodoWrite` on Claude Code)        | `todo` when enabled. Otherwise keep the `todo.md` checklist that poteto-mode describes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Ask the human a fixed-choice question (`AskUserQuestion`)                                     | `ask_user_question`, same shape. Without an interactive UI (print or JSON mode), and in a subagent, it returns an error, so ask in plain text.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Schedule a self-paced re-invocation (`ScheduleWakeup`)                                        | `schedule_wakeup`, same shape. A due wakeup stays pending until the session is idle, including during manual compaction. `noop: true` only labels the wakeup, which is still scheduled, and `stop: true` cancels the pending wakeup and needs no other field. In print and JSON mode, and in a subagent, scheduling returns an error. After a `/loop` command ends or replaces the loop during a run, that run is refused every wakeup until it settles, whatever the prompt, and Pi tells the user. No other wakeup is refused.                                                                                                                                                                                                                                    |
| Read this workspace's session transcripts (Claude Code's `~/.claude/projects/<encoded-cwd>/`) | Pi sessions live in `~/.pi/agent/sessions/--<cwd>--/` (under `$PI_CODING_AGENT_DIR` when set), where `<cwd>` is the working directory without its leading `/` and with each `/` as `-`. Subagent sessions are in the same directory, because each subagent is a pi session in the same working directory. Each file opens with a `session` header line; every later line is an entry with an `id` and a `parentId`, and a message entry is `type: "message"` with `message.role` `user`, `assistant`, or `toolResult`. A session keeps abandoned branches in the same file, so follow `parentId` back from the last entry for the conversation that happened. The same privacy rule applies: read only this workspace's directory, never a glob across `sessions/`. |

The `subagent_*` tools work only when pi runs in a herdr pane. Without them, and in a subagent,
which does not get the subagent tools, the fan-out skills (`interrogate`, `why`, `how`, `arena`,
`reflect`) degrade to a single sequential pass. A required independent review does not degrade. It
stays blocked, as poteto-mode's [Subagents](../SKILL.md#subagents) section says.

## Subagent policy

poteto-mode's Subagents section applies on Pi through `subagent_start`:

- There is no `subagent_type` parameter. For a pstack agent type, start the `task` with an
  instruction to read the agent file in full and follow it, then give the work. The agent files are
  in the `agents/` directory of the pstack package, three levels above this file
  (`../../../agents/`). Give the subagent the absolute path:
  - `pstack:poteto-agent` (and `pstack:poteto-agent-<level>`): `agents/poteto-agent.md`. Also give
    it the absolute path of the poteto-mode `SKILL.md`, as that file says.
  - `pstack:thermo-nuclear-review-subagent`: `agents/thermo-nuclear-review-subagent.md`.
  - `pstack:thermo-nuclear-code-quality-review-subagent`:
    `agents/thermo-nuclear-code-quality-review-subagent.md`.
  - `general-purpose` (and `pstack:effort-<level>`), or no `subagent_type`: no agent file. Claude
    Code's built-in types such as `Explore` and `Plan` do not exist on Pi, so put the constraint in
    the task.
- There is no `readonly` parameter. When a skill sets `readonly: true`, say in the task that the
  subagent must not change files. It can still run commands such as `git diff`.
- There is no `isolation` parameter. When a skill sets `isolation: "worktree"`, make a git worktree
  for the subagent yourself (`git worktree add`), and put its absolute path in the task. Tell the
  subagent to work only in that directory. Remove the worktree when it holds no work that you need.
- There is no `run_in_background` parameter. Every subagent runs in the background, and
  `subagent_start` returns at once.
- A subagent does not get the subagent tools, so a subagent cannot start its own subagents. When a
  skill tells a subagent to fan out, do the fan-out in the main session, or tell the subagent to do
  the work in sequence.
- A subagent is an interactive pi session, not a one-shot process. When it stops, it closes, and you
  get its last reply. A subagent that is blocked, for example on an approval dialog, stays open.
  `subagent_send` to a closed subagent resumes it in a new pane with its full history.
- Subagents belong to the session that started them. When you quit pi or change the session, pi
  stops them.
- Keep the rest of the policy unchanged. Pass file pointers not inlined context, give each worker
  its own worktree when they write, review every subagent's diff yourself.

## Model names

Skills name models by the Claude aliases in their Models sections. On Pi, `subagent_start` takes a
`model` as `provider/model`, not an alias. Find the column of the provider of the current session,
and use the `anthropic` column for any other provider:

| Alias    | `anthropic`                   | `openai`             | `openai-codex`             |
| -------- | ----------------------------- | -------------------- | -------------------------- |
| `opus`   | `anthropic/claude-opus-5-5`   | `openai/gpt-6.1-sol` | `openai-codex/gpt-6.1-sol` |
| `fable`  | `anthropic/claude-fable-5-1`  | `openai/gpt-6-astra` | `openai-codex/gpt-6-astra` |
| `sonnet` | `anthropic/claude-sonnet-5-5` | `openai/gpt-6-sol`   | `openai-codex/gpt-6-sol`   |
| `haiku`  | `anthropic/claude-haiku-5-5`  | `openai/gpt-6-luna`  | `openai-codex/gpt-6-luna`  |

A `pi models: opus=<provider/id>, sonnet=<provider/id>` line in the Pi override sheet points each
alias it names at another Pi model, whatever the provider of the session. That line is in your
system prompt when the sheet has it, and it has priority over the table. `inherit-parent`, `auto`,
or no model: omit `model`, and the subagent runs on your model. `subagent_start` returns an error
when the model is unknown or has no auth. Then omit `model`, and say so in your reply.

Diverse-model panels (`arena`, `architect`, `interrogate`, `how` critics, `reflect`) stay diverse
only while their aliases resolve to distinct models. If you can reach only one model family, say in
the verdict that diversity was reduced.

`subagent_start` cannot set a reasoning effort. A subagent runs at the default thinking level of pi.
Ignore an `@<level>` on a role value, and keep the model that the role names.

`/setup-pstack` writes the configured model list. On Pi, keep the aliases and remap them with
`pi models:`.

## Session routing

The pstack Pi extension adds the poteto-mode mandate, the text the Claude Code and Codex
`SessionStart` hook injects, to the system prompt at every agent start, so the mandate survives
compaction. It also adds the Pi override sheet, because Pi has no include syntax for context files.
The sheet is `pstack-models.md` in the Pi agent directory, which is `$PI_CODING_AGENT_DIR` when set
and `~/.pi/agent` otherwise. `session hook: off` in the sheet stops the mandate. Subagents get the
sheet but not the mandate, as Claude Code subagents see CLAUDE.md but run no `SessionStart` hook.
Every session, subagents and sessions with the hook off included, also gets a pointer to this file
and Claude Code's sentence on making independent tool calls in one response.

## Driver and bundled skills pstack references

The [driver policy](../SKILL.md#non-negotiables) selects the app driver. For skills and drivers
named by these workflows, use these Pi equivalents:

| Skill or driver named in pstack                                                       | On Pi                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `run` (drive a CLI/TUI to see a change work)                                          | Pi has no `run` skill. Run the app yourself via `bash` and observe the real output.                                                                                                                                                                                                                                                         |
| `verify` (the project's `.claude/skills/verify/`, or Claude Code's bundled `/verify`) | Pi does not discover `.claude/skills/`. Read the project skill's SKILL.md by path, or add `../.claude/skills` to the `skills` list in `.pi/settings.json`. Without a project skill, drive the app as for `run`.                                                                                                                             |
| Project UI driver                                                                     | Drive the UI with whatever automation you have, or hand the user a concrete manual check. Do not claim done without observing the artifact.                                                                                                                                                                                                 |
| `plugin-dev:skill-development` (Claude's SKILL.md authoring guidance)                 | Follow Pi's skills documentation and the Agent Skills specification. Keep `name` + `description` frontmatter, name the directory after the skill, and use progressive disclosure.                                                                                                                                                           |
| `loop` (recurring/self-paced re-invocation, used by `babysit`)                        | The extension's `/loop [interval] <prompt>` command. With an interval it re-fires on that cadence. Without one the prompt runs now and the model paces itself with `schedule_wakeup`. `/loop stop` cancels, also while an iteration runs: nothing that run then schedules is armed. A `/loop` given during a run starts once that run ends. |

## Vendored scripts

`skills/poteto-mode/scripts/` ships the `watch-pr` PR watcher, the `orch` store CLI, and
`worktree-audit.mjs`. These scripts use bun and Node.js and run the same on Pi; invoke them through
`bash`. They need `bun` and `gh`, or `origin` when the forge is Origin. Run `worktree-audit.mjs`
with `node`, as its shebang does. `worktree-audit.mjs` finds the last chat of each worktree in each
transcript directory of a runtime that exists, Pi's `sessions/` under `$PI_CODING_AGENT_DIR`
(default `~/.pi/agent`) included. Pass transcript directories after the repo path to scan others
instead. It imports the transcript walker from `skills/reflect/scripts/find-transcript.mjs`, so keep
the `reflect` skill installed beside `poteto-mode`.

## Instructions file

Where a pstack skill says "your instructions file", on Pi that is `AGENTS.md` or `CLAUDE.md`, which
Pi loads from the working directory and each parent directory, plus `~/.pi/agent/AGENTS.md` for
every directory. On Claude Code it is `CLAUDE.md`.
